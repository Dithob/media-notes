# 输出规则

## 主稿与副产物

主稿只写用户真正需要阅读的内容。完整时间轴、逐条证据、覆盖判断、背景补充和无法
确认项放到来源 ID 目录：

```text
media-artifacts/
├── <主稿文件>.md
└── <source-id>/
    ├── README.md
    ├── raw-subtitle.json
    ├── metadata.json
    ├── transcript.md
    ├── timeline.md
    ├── evidence.md
    └── boundaries.md
```

主稿末尾只保留简短的副产物导航，不要把副产物全文复制进主稿。

## 文件名

- 总结笔记：`<媒体标题>摘要.md`
- 详细总结：`<媒体标题>详细总结.md`
- 结构梳理：`<媒体标题>结构梳理.md`
- 操作手册：`<软件或主题>操作手册.md`
- 学习文档：`<媒体标题>学习笔记.md`
- 时间轴转录：`<媒体标题>时间轴转录.md`

标题过于泛化时，根据字幕提炼主题；操作手册优先使用软件、产品或主题名称。

## 证据标签

- **字幕已验证**：字幕或媒体元数据直接支持；
- **背景补充**：来自模型知识、本地资料或联网搜索；
- **当前任务判断**：Codex 根据用户目标做出的归纳；
- **无法确认**：字幕缺失、含混或证据不足。

结构章节应标记为“基于字幕推断”，不能称为官方章节。用户要求当前版本、价格、法规
或外部核验时，才搜索网络，并把结果标成背景。

## ASR 还原的落盘约定

> **零词条原则**：本 skill 只规定**规则与表头模板**，不保存任何真实 ASR 词条。
> 词条数据一律只存在于主产物根目录同级的 `asr-corrections/` 目录（项目另有约定时以项目为准）。
> 理由：词条随视频持续增长而规则几乎不变（稳定性）；skill 每次调用都进上下文（体积）；
> skill 会被 `npx skills add` 装到他人项目里，某门课程的专有对照表对别人无意义（跨项目污染）。

### 目录结构

误识别由讲者口音决定，**按讲者（作者）组织**，不按笔记组织：

```text
<主产物根目录>/asr-corrections/
├── README.md               # 索引：作者 → 对照表文件
├── <作者>.md               # 该讲者的 ASR 还原对照表（只放已确定的映射）
└── 存疑清单.md             # 待人工审核的存疑项（与对照表分离，按作者分组）
```

### 文件结构

对照表文件（`<作者>.md`）只放已确定的「误识别变体 → 正确术语」映射：

```markdown
# <作者> · ASR 还原对照表

| 字幕原文 | 还原为 | 依据 |
| --- | --- | --- |
```

存疑清单独立成文件，含「待人工审核」与「已查证（回看）」两组：

```markdown
# 存疑清单（待人工审核）

## <作者>
### 待人工审核
### 已查证（回看）
```

### 规则

- **先查后写**：动手前先读该讲者的 `<作者>.md`，命中即复用，发现新变体补回该作者的对照表；
- 主稿只留一行指针（指向作者对照表 + 存疑清单），不要把对照表整段复制进主稿；
- **拿不准的进存疑清单**，别硬塞进对照表——对照表只放确定的，存疑的单独列在 `存疑清单.md` 待人工审核；
- **必须联网查证**：包名、CLI 命令名、启动参数、文件路径、API 方法名、技术术语缩写。
  标注“存疑”不等于免责——凭谐音猜出来的包名基本都是错的；
- **可以只标存疑**：模型版本号、UP 主昵称、视频未展示的命令原文、无法穷举的第三方列表；
- 查证后在主稿标注来源，并把结论同步到存疑清单的「已查证（回看）」分组。
