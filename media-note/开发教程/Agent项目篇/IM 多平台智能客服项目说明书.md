## 1. 项目背景与要解决的问题

IM（即时通信）生态碎片化：微信、企业微信、QQ、飞书、钉钉，海外还有 Telegram、Slack、Discord、LINE。每家公司做智能客服，都希望覆盖用户所在的 IM，但传统做法是**每个平台单独开发一套**：

- 各平台 SDK / API 细节不同，接入成本高；
- 每套都要单独做监测、运维、升级；
- Agent 逻辑升级要逐平台重复发布。

**解法**：把"AI 大脑"与"IM 收发"解耦——

- **Dify**（LLM 应用开发平台）：负责思考、决策、知识管理，可视化编排 Agent / Chatflow / RAG，应用可暴露为 Web 应用和标准 API，自带日志与监测；
- **LangBot**（开源 LLM 原生 IM 机器人平台）：负责嘴巴和耳朵——对接企业微信、飞书、钉钉、QQ、Telegram、Slack、Discord、LINE 等，一个机器人 + 流水线适配多平台，把 IM 消息转给 Dify（或自带内置 Agent）并把回复发回。

```text
┌─────────┐   ┌─────────────┐   ┌──────────────────────┐   ┌─────────┐
│ 用户     │→ │  IM 平台     │→ │  LangBot（收发网关）    │→ │  Dify   │
│ (企微/飞书│  │  机器人/应用  │  │  机器人 + Dify 流水线    │  │ Chatflow│
│  /微信等) │← │             │← │  消息转发 / 日志        │← │ RAG/Agent│
└─────────┘   └─────────────┘   └──────────────────────┘   └─────────┘
  提问/回复     应用权限配置       企微 5 项 / 飞书 2 项凭证      发布 API + 密钥
```

## 2. 组合优势（为什么是 Dify + LangBot）

### 2.1 极速接入：不用为每个平台写适配代码

- LangBot 已封装各 IM 平台的 SDK / API 细节，提供**统一的 IM 接入层**；
- 对接新平台只需用同样的"机器人 + 流水线"方式，找到该平台的关键配置即可；
- Dify 侧：拖拉拽编排 Agent 逻辑，应用既可作为内嵌 Web 应用，也提供标准 API 供 LangBot 调用——把 RAG / Agent / Chatflow 等能力直接暴露给 IM。

### 2.2 一次开发、多平台部署 + 统一管理

- Agent 的 AI 部分只存在于 Dify：一个 Dify 应用 API 可被多个 IM 平台复用；
- 对话日志、用户反馈、调用情况（会话数、每秒/消耗 token）在 Dify 后台统一查看；
- 升级 Agent 只需升级 Dify 中的应用——所有 IM 平台同步生效；可做灰度测试、多版本发布。

### 2.3 多模态能力

- Dify 可接入多模态大模型（图像识别、图文并茂回答）；
- LangBot 负责把文本、图片、语音、文件正确送达；
- 示例：电商退货场景，用户上传包裹破损照片 → Agent 识别"外包装严重破损、挤压变形" → 直接转入物流投诉流程，替代人工审核。

## 3. 典型应用场景

### 3.1 全渠道智能客服

- 电商售前售后咨询、金融产品业务办理指导（金融业务复杂，SOP 明确，很适合）；
- Dify 中一条 Chatflow 即可完成：**问题/意图分类 → HTTP 请求 → 变量收集 → 标准客服动作**；
- 能力演进路径：大模型 → +知识库（FAQ / 疑难杂症，即 RAG）→ +多模态（识别语音、图像）→ +个性化推荐 → 全渠道作答 → 自学习闭环；
- 本质：人工客服的权限与动作本就被 SOP 约束，AI 客服只是把这套流程自动化。

### 3.2 群助手（社群运营）

- 技术社群答疑机器人、项目群进度助手；功能包括信息聚合问答、任务提醒通知、智能陪聊；
- 示例：HR BP 群助手自动发节假日调休通知；群精华总结（把当天 IM 讨论整理成摘要）；
- 关于实时性：大模型走 embedding + 向量检索 + API 调用，响应是秒级到十秒级；但十秒能输出几百字高质量内容，人工做不到——**按业务取舍：不差这 10 秒就把优化优先级放到"生成质量"上**（跳出盒子 out of the box 思考）。

### 3.3 工作流自动化入口（企业内部）

- 在企业微信查客户信息、在飞书发起员工入职/离职、请假审批等内部流程，从"填表单"变成"自然语言一句话发起"；
- 示例：员工说"国庆后请 5 天年假"→ Agent 抽取参数（请假类型/天数/开始结束日期/提交时间）→ 意图理解 → 假情校验（年假余额够不够）→ 生成并提交申请单 → 启动审批 → 状态反馈与通知；
- 附带价值：帮审批人做总结、快速决策，优化多级无效审批。

## 4. 实战一：企业微信「雪茄通」RAG 智能客服（p15，16:09）

### 4.1 场景

企业微信上部署一个"雪茄百科知识问答"RAG 客服（演示品牌名"雪茄通"），用户提问如"送领导 5000 预算买什么雪茄""69% 保湿包是什么"。

### 4.2 三方配置清单（一次打通三步）

| 环节 | 要做的配置 |
| --- | --- |
| **Dify 平台** | ① 已有已发布的 RAG Chatflow 应用；② 「日志与标注」统一查看所有 IM 来源的会话；③ 「监测」看调用量与多维度指标；④ 「访问 API」生成 **API 密钥**，Base URL 形如 `api.dify.ai/v1`，应用类型选 **聊天 / Chatflow** |
| **LangBot 平台** | ① 新建「Dify 流水线」：运行器从"内置 Agent"改为 **Dify 服务 API**，填 Base URL + 应用类型 + API 密钥；② 基于该流水线新建**企业微信机器人**（不再走内置逻辑，而是调 Dify） |
| **企业微信平台** | ① 创建自建应用（如"雪茄通智能客服"）；② 配置可信 IP（指向 LangBot 服务器）；③ 应用与权限沿用课程此前已完成的配置（企业 ID、Token、加解密密钥、通讯录密钥等，需在企微后台一次性配好） |

### 4.3 使用与效果

- 企业微信工作台可访问该应用，也可在微信内直接对话（企业成员）；
- 提问后回到 Dify「日志与标注」可看到会话按话题自动整理、引用知识库来源；
- **坑**：DeepSeek 默认输出 Markdown，企业微信不渲染——在提示词里要求生成纯文本，避免加粗/缩进/序号等格式。

## 5. 实战二：飞书「高考志愿填报」智能客服（p16，20:18）

### 5.1 场景

飞书上部署高考志愿填报助手：考生报省份/分数/兴趣，得到院校与专业建议。本课先用 LangBot 内置 Agent 快速跑通，把"再接 Dify"留作作业（复刻企微那套）。

### 5.2 飞书侧完整流程（开放平台 open.feishu.cn）

1. **注册并进入开发者后台** → 「创建企业自建应用」：填名称、描述、图标（图标可用豆包 / GPT-4o 等文生图生成）；
2. **添加应用能力**：选「机器人」（飞书预制能力，也可加多维表格等）；
3. **权限管理**：开通免审核权限——"获取与发送单聊消息""接收群聊中@机器人消息事件"；需审核的（用户身份/应用身份）另行申请；
4. **凭证**：只需两项——**App ID、App Secret**（比企业微信少，企微有 5 项）；
5. **事件与回调**：订阅方式选**长连接**（推荐，默认）；服务端需返回 HTTP 200 确认；添加「接收消息」事件（单聊 + 群聊@）；
6. **版本管理与发布**：按语义化版本写 `0.1.0` → 发布，即可在飞书搜索到机器人。

> ⚠️ 顺序坑：长连接模式下，先到 LangBot 把飞书机器人和流水线配好（填 App ID / App Secret，开好端口），**再回飞书添加事件**——否则添加事件会失败。

### 5.3 LangBot 侧

- 新建**飞书机器人**：填 App ID / App Secret；
- 新建/选用流水线：示例用**内置 Agent** + 提示词（"你是高考志愿填报专家，用通俗语言回答"）；
- 作业升级路径：把运行器切到 **Dify 服务 API**（复用第 4 节企微配置法），再接 RAG 知识库（分数线/院校库），有能力的再加联网搜索。

### 5.4 演示与提醒

- 演示提问："四川理科 666 分学计算机报什么院校" → 列出清北/上交/浙大/中科大/南大/电子科大等参考（内置 Agent 无知识库时的回答）；
- **提醒**：无知识库时模型给的分数参考不一定准确——这正是作业要接 RAG 的原因；
- LangBot 插件：可按需安装社区插件，选 star 多、无恶评的（生态仍在规范化中）。

## 6. 关键配置速查

| 平台 | 凭证/配置项 | 数量 |
| --- | --- | --- |
| 企业微信 | 企业 ID、Token、加解密密钥、通讯录密钥、可信 IP（指向 LangBot 服务器） | 约 5 项 |
| 飞书 | App ID、App Secret（+ 事件订阅长连接） | 2 项 |
| Dify | 应用 API 密钥 + Base URL（`api.dify.ai/v1` 示例）+ 应用类型（聊天 / Chatflow） | 随应用 |
| LangBot | 机器人（各平台凭证）+ 流水线（运行器：内置 Agent 或 Dify 服务 API） | 随平台 |

## 7. 课程作业（可做延伸项目）

1. 企业微信侧：按 p15 指导，独立完成一个"RAG 智能客服 + LangBot 接企微"的端到端实践（不限于雪茄，可换任意主题）；
2. 飞书侧：在课程内置 Agent 基础上，**把 Dify 应用接上飞书**，做成带知识库的 RAG 高考志愿客服（复刻企微流程）；
3. 有能力的：加联网搜索、多模态。

## 8. 可复用方法论

- **AI 能力与渠道接入解耦**：凡"一套 AI 逻辑要铺到多个终端"的需求（客服、群助手、内部流程入口），都可套 Dify + LangBot 两层模型；
- **先用内置 Agent 跑通、再接 Dify**：降低首版门槛，验证场景后再上 RAG / 工作流；
- **观测先行**：Dify 日志/监测 + 可选 LangSmith，让多渠道客服可运维；
- **提示词适配渠道**：不同 IM 对 Markdown/富文本支持不同，发布前按渠道约束输出格式。
