## 0. 先看结论

- **业务场景**：任何公司都有销售团队。销售要做的三件事——①整理用户信息，②判断用户是 A/B/C/D 哪类意向客户，③针对不同类别定制跟进策略。这三步高度适合交给 AI，人工只做策略执行；
- **技术选型**：不必从零写 Agent 代码，直接用多 Agent 编排框架 **CrewAI**：用**大白话提示词**定义 Agent（角色/目标/背景），用任务模板定义 Task，再给任务配 Agent 和工具，最后"组装"起来运行；
- **Demo 成果**：两个 Agent 自动完成"搜索目标公司公开信息 → 生成公司综合分析报告（背景/业务/客户/合作机会）→ 起草多轮销售跟进邮件"，且带**输出质量筛查**（情感分析伪代码做评分门槛，不达标继续生成）；
- **实操要点**：支持**国产模型接入**（本课用 DeepSeek 而非默认的 OpenAI），支持框架**内置工具**（文件阅读、搜索/检索）与**自定义工具**（如情感分析），任务输入用**占位符**做模板化（{company} 等），换客户只需改配置。

## 1. 业务场景与"人机分工"

销售团队常做的事：

| 步骤 | 内容 | 交给谁 |
| --- | --- | --- |
| 1 | 整理用户信息 | AI（自动收集） |
| 2 | 判断意向等级（A/B/C/D 类客户） | AI（基于指标分类） |
| 3 | 基于等级定制跟进策略 | AI（生成策略），人执行 |

- A 类怎么跟踪、B/C/D 类怎么维护关系，依据是公司规模、行业、业务、地域 + 自家产品做匹配，判断"哪类人更容易成交"；
- **效率收益**：数据收集、客户分类、策略生成全交给 AI，人只做跟进执行 → 销售效率与成交率提升。

## 2. 为什么不需要从零写 Agent

课程强调：今天有很多 **AI 开发框架**帮你快速搭建项目，比如 **LangChain**、**CrewAI** 等。本课用的是 **CrewAI**。

> 对没有编程基础的同学，课程建议：让大模型帮你解释代码、学习代码，代码本身不是核心难点，**理解整体逻辑**才是。

## 3. CrewAI 实战拆解：把 Agent 想象成"人"

### 3.1 定义 Agent（config/agents 或 .py 内配置）

课程把 A 级（Agent）想象成一个人，需要定义：

- 这个人是干什么的（**角色 role**）；
- 工作目标是什么（**goal**）；
- 背景/身份（**backstory**）——比如"你是销售团队一员，要借助工具……"

本课定义了两个 Agent：

| Agent | 定位 | 职责 |
| --- | --- | --- |
| **销售代表（Sales Rep）** | 负责收集信息 | 在客户中找高价值潜在客户，收集公司公开信息并整理分析 |
| **高级销售代表（Senior Sales Rep）** | 负责成交 | 基于收集到的信息，制定销售跟进策略（写邮件） |

### 3.2 定义 Task（任务模板）

Tasks 文件里用**占位符**（如 `{company}`）让任务可复用——因为每家公司、行业、联系人都不同。占位符的实际值在 main 文件里传入。

本课两个 Task：

1. **对公司进行分析**：维度包括公司背景、业务模式、所属行业、可用的数据来源、重点关注的方面，最终输出一份分析报告（收集什么信息 → 得出什么报告）；
2. **基于报告做洞察与外联**：对收集到的报告做数据分析和洞察 → 输出一份**销售跟进邮件**（核心目标：价值观共鸣、展现对公司业务的理解 → 这是"业务认知"）。

> 做大模型落地，一边是技术，一边是对**业务场景的认知**——两者都重要。

### 3.3 组装（crew.py）：配人、配任务、配工具

CrewAI 项目结构（经典模式，参考官方脚手架）：

```text
project/
├── config/            # agents.yaml / tasks.yaml（或 .py 内联定义）
│   ├── agents.yaml
│   └── tasks.yaml
├── crew.py            # 组装：加载 agent → 建 task → 配工具 → 组装 crew
├── tools/             # 自定义工具（也可以不建目录，直接内联）
└── main.py            # 入口：传实际输入（公司名等），触发执行
```

组装要点：

- **加载配置**：把 agents/tasks 配置加载进来；
- **初始化 Agent**：把两个"人"加载出来；
- **任务配置**：每个 Task 指定——谁来干（配 agent）、做什么事、配什么工具、最终输出到哪个文件（output file）；
- **配工具**：
  - **框架内置工具**：文件阅读（读指定文件夹下的销售规范/优秀案例做参考）、检索工具等；
  - **自定义工具**：写自己的工具（课程用"情感分析"伪代码演示）——对生成的邮件做评分：**达到指标就输出，达不到就继续生成调整**；
- **运行**：`python main.py`（课程另做了一个带日志的演示文件，方便看 Agent 完整执行流程）。

### 3.4 关键细节：国产模型接入

CrewAI 默认使用 OpenAI 接口。国内用户可以用国产模型，本课用的是 **DeepSeek（字幕"deep sec / deep sick"）**，通过配置国产模型的 OpenAI 兼容 API 接入。课程原话：很多人没有 OpenAI key，用国产模型即可。

## 4. 运行效果：Agent 的完整工作流

课程运行带日志的演示文件，展示了两个 Agent 的完整执行链路：

1. **初始化**：代理（Agent）初始化完成；
2. **销售代表开始干活**：
   - 思考：先了解公司基本情况 → 先搜索互联网获取公司信息；
   - **使用工具**：互联网搜索（工具输入是 URL 编码的中文关键词）；
   - 基于搜索结果打开多个网页（官网、新闻、采访）→ 综合出 **公司的综合分析报告**，内容含：
     - 公司名称、成立时间、总部位置、行业定位；
     - 关键人员/老板信息；
     - 业务模式、客户群体；
     - 合作伙伴（课程演示公司如"广东核电/西门子"等，为示例数据）、生态伙伴；
     - 近期业务发展、影响力；
     - **潜在合作机会识别**：根据公司特点，列出可合作的价值领域、匹配点、个性化互动策略、长期合作建议（行业活动、技术演示、合作模式、沟通机制）；
   - 需要更多信息时，会**继续搜索**关键人员近期发展与具体产品信息；
3. **高级销售代表登场**：
   - 基于分析报告 → 起草外联活动（如"大模型商业实战训练营"）；
   - 搜索老板/目标人物相关信息 → 对搜索结果做**情感分析/质量筛查**（防止搜到负面内容混进输出）；
   - 输出**销售跟进邮件**草稿，课程展示了多版：初步跟进（"强强联合，共筑大模型 AI 平台新时代"）→ 战略合作邀约 → 价值共创 / 合作推进邮件。

**效果对比**：这些事如果人工做，要挨个打开网页、汇总内容、再分析写邮件；Agent 全自动完成。

## 5. 可复用经验

- **只改配置就能换业务**：换一家客户/行业，改配置文件或 main 里的输入即可，Agent 逻辑不用动；
- **可以再叠自定义工具**：接自己的 API 或写特殊评分逻辑（情感/质量门槛）；
- **进阶玩法**：想改代码，可以继续用 Claude Code / CodeBuddy 这类工具在此基础之上完善（字幕"cloud code"，同类工具未指名，存疑）。
