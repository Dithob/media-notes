## 0. 先看结论

- **客服/工单是 Agent 落地最密集的板块**：把产品 API 文档、使用手册做成知识库，前端接用户截图/语音，Agent 分析图文 → 检索知识库 → 生成回复给人工客服参考，直接提升回复效率与满意度；
- **编程场景的工具值得关注**：MetaGPT 用多角色模拟软件公司（给需求即可跑完整流程）；Cover Agent 用自然语言生成测试、收集代码库信息增强测试、产出覆盖率报告——有团队 12 个测试工程师借此缩到 3 人；
- **传统工业（B 端/国企）是大模型最难啃但回报最厚的场景**：设备预测性维护项目把传感器/监控/历史维修等多源数据汇成知识库，产出健康度评估、根因分析、预测维护等能力；客户效果：设备效率 +12%、平均故障间隔延长 3 倍、检修时间 -60%、新工程师上手 -50%，并因此签下 3 年 2000 万美金合同；
- **对做测试的同学特别提醒**：所有产品都在 AI 化，未来测试不只是功能/压测，**针对大模型的评估与测试**是一个很有前景的方向。

## 1. 客服板块：HubSpot 售后工单智能体

**HubSpot（字幕 hub sport/HABSPORT）**：美国 SaaS 公司，主打 CRM 等传统企业软件（国内也有类似厂商）。

- 痛点：软件卖出后要有专业售后，客户遇到复杂使用场景，售后需专业跟进与支持；
- 做法（UP 主团队一年多前做的早期产品）：
  1. 把 HubSpot 大量的 **API 文档、使用手册**做成知识库；
  2. 前端接收用户需求——**截图或语音**；
  3. Agent **分析图像 / 文字** → 到知识库检索相关模块内容 → 整理成回复文本；
  4. 回复给后端客服人员做**参考**；
- 效果：提升整体回复效率、提升客户满意度。

> 一句话：智能客服是 Agent 落地最多、最成熟的板块。

## 2. 软件开发场景：MetaGPT 与 Cover Agent

### 2.1 MetaGPT：模拟一家软件公司

**MetaGPT（字幕 mate g b t）**：开源的多 Agent 框架，应对"软件开发"场景。

- 框架里已定义好软件公司的完整角色：老板、产品经理、架构师、项目经理、工程师、测试……每个 Agent 的身份都预设好了；
- 提供"软件公司完整流程"的 **SOP（精心策划的标准作业流程）**——不同的人该怎样干活已被定义好；
- 使用体验：**你只要给需求**，剩下全自动。

> 上一课的 CrewAI 需要你自己定义角色和任务；MetaGPT 更进一步，角色和流程都内置了。

### 2.2 Cover Agent：测试生成 Agent

**Cover Agent（字幕 child cover / chat cover，疑与"cover agent"同指）**：AI 测试工具，定位是软件测试。

- 能力：
  1. 通过**自然语言生成对应的测试用例**；
  2. 从你的**代码库收集对应代码**来增强测试能力；
  3. 生成**测试覆盖率报告**；
- 案例（UP 主合作伙伴的真实故事）：原团队 12 个测试工程师 → 结合 Cover Agent → **测试团队缩到 3 人**，整体优化明显。

> 给做测试的同学的话：现在所有产品都在往 AI 化发展，未来的测试不只功能测试/压测/性能测试，还有**针对大模型的评估与测试**——这也是个很好的方向。

## 3. 传统工业场景：设备维护 Agent（B 端案例）

UP 主团队主要服务 B 端客户，对接国企较多。这是他们在传统工业场景的一个实战案例。

### 3.1 需求与产品形态

机械设备需要维护/检修/日常分析，最上层做了四类产品：

| 产品 | 面向谁 | 干什么 |
| --- | --- | --- |
| 管理层决策报告 | 管理者 | 机器到了对应阶段自动生成维护工单（像汽车保养），产出决策报告 |
| 维护工单 | 流程 | 机器到阶段自动生成维护工单 |
| 工程师智能问答助手 | 工程师 | 设备出故障 → 分析故障、给维修策略、用哪些零件 |
| 车间主任日常看板 | 车间 | 全车间机器状态、产量等 |

### 3.2 数据与知识库构建

大模型产品第一步是数据。多源异构数据共同构建知识库：

- **传感器数据**（振动、声音）→ 故障分析；
- **机器视觉**（监控数据）；
- 设备控制系统、历史数据库；
- 非传统数据：**老师傅的维修记录**、手账、历史故障报告、设备操作标准 **SOP**。

> 数据很杂（文本/图像/音频混合），不能只用纯 LLM——要么做**路由**分发给不同模型再汇总（早期做法），要么直接用**多模态大模型**做综合处理（现在更主流）。

### 3.3 应用能力与量化效果

在数据 + 大模型 + 定制流程之上，形成功能：**健康度评估、根因分析、预测性维护、维护方案自动推进**。

客户侧的量化收益：

| 指标 | 效果 |
| --- | --- |
| 设备效率 | **+12%** |
| 平均故障间隔时间 | **延长 3 倍** |
| 机器检修/修复时间 | **缩短 60%** |
| 新工程师上手（设备检修） | **缩短 50%**（不再只依赖老师傅经验） |
| 决策报告 | 全部由 AI 生成 |
| 附带收益 | 质量/良品率与稳定性提升 → 客户续签 **3 年期 2000 万美金合同** |

> 对大模型落地的现实体感：业务场景没接触过也没关系——和客户反复讨论梳理需求、梳理逻辑、找到实现路径，先从小功能推，再不断完善。

## 4. AI 时代的思维转变（收尾）

- 现在跟外界谈业务，不谈 AI/大模型就像落伍了；
- **技能的"保质期"在被急剧缩短**：过去学一门开发技能要培训机构半年起步、熟练要几年；现在完全不懂代码的人也能用 AI 做产品；
- 类比"马鞭"：汽车普及后，马鞭做得再精美也没了用武之地——死磕旧技能无法登上未来的船；
- 结论：不是技术本身，而是**思维方式要改变**——"思维方式决定人生方向"；
- 反问：我们手里拿的是不是一张渐渐失效的旧地图？现在熟练的能力，3~5 年后会不会变成 AI 时代的马鞭？**学新东西最重要的一点是提升认知**。
