## 0. 先看结论

- **Agent 的本质**：把人与大模型"多轮对话、逐轮纠偏"的过程自动化——由大模型参与决策、分析、辅助纠偏，自主完成"理解需求 → 拆解任务 → 调用工具 → 汇总输出"的闭环，直到达成总目标；
- **Agent = 大模型（大脑）+ 规划 + 记忆 + 工具**：四要素缺一不可。规划靠提示词（如 CoT 思维链）引导，记忆分短期/长期（长期可外挂知识库 = RAG），工具即传统应用里的 API；
- **单 Agent 的局限**：像"全栈工程师"一样什么都会但都不精——任务越杂，效率与准确性越低；
- **多智能体协作的价值**：让不同 Agent 专注单一场景（各自挂不同模型/工具/知识库），通过分工协作提高整体效率与准确率；
- **三种常见协同范式**：上下级协同（中控 Agent 拆任务给子 Agent，飞猪是典型）、师生式协同（专家/学生互相讨论迭代）、竞争式协同（多个 Agent 各自产出再择优）。

## 1. 为什么需要 Agent：人与大模型单轮对话的局限

课程先讲了"我们平时怎么用大模型"：

- 给大模型发一个 **prompt（自然语言）** → 模型返回结果；
- 不满意 → 人工再提要求 → 模型再改 → 循环往复。

这个循环最大的卡点是**人**：

- 人工阅读回复 → 判断质量 → 给出指导意见，受限于个人时效性；
- 每次都要人盯着，无法规模化。

> **课程结论**：如果让大模型参与决策、分析、辅助纠偏，把"人的判断环节"也交给模型，就构成了一个 **Agent**。简单说：Agent 就是把整个目标流程"代理"（代替）给机器执行。

## 2. Agent 长什么样：以"飞猪"为例

课程用**飞猪 App**（阿里旗下在线旅游平台，字幕误识别为"飞猪/非洲"）讲 Agent 的完整工作方式。

一个用户去旅游的需求，至少要考虑：预算、人数、交通方式（飞机/高铁哪个便宜方便高效）、老人小孩、目的地玩法天数、路线规划、出发时间、酒店……

飞猪收到需求后，会像人一样：

| 步骤 | 行为 | 对应 Agent 能力 |
| --- | --- | --- |
| 1 | 理解用户说的话 | **理解需求** |
| 2 | 把需求拆成 1234 可执行的任务/流程 | **任务拆解（规划）** |
| 3 | 针对每个子任务调用不同工具（查机酒、查攻略、查天气、查路线……） | **调用工具** |
| 4 | 基于各工具结果，按步骤综合 | **编排执行** |
| 5 | 结合原始需求汇总输出结果 | **汇总输出** |

**和传统大模型单轮对话的差异**：设定一个总目标后，Agent 会一直执行到目标达成——每步执行完得到中间结果，继续往下走，而不是"捅一下动一下"。

课程点睛：

- 传统行业（旅游、CRM 等）用大模型结合有巨大优势——**你拥有别人没有的数据**，如飞猪自带大量机酒与攻略数据；
- Agent 翻译过来叫"代理"，代理的是"你这个人"或"某一个流程"；
- 可以把 Agent 想象成一个**员工/助理**。

## 3. Agent 的核心组成：一张经典图

课程引用了一张图，来自 OpenAI 安全研究员 **Lilian Weng（字幕误识别为"莉莉安问/温丽莲"）** 的早期博客（即经典的 "LLM Powered Autonomous Agents" 一文），目前流传非常广。

Agent = 大模型（核心大脑）+ 三类关键能力：

```text
                    ┌─────────────────────────────┐
                    │         大模型 (LLM)          │  ← 核心大脑 / 决策中枢
                    └─────────────────────────────┘
                      ▲         │         │
          ┌───────────┘         │         └───────────┐
          │                     │                     │
   ┌──────┴───────┐    ┌────────┴────────┐   ┌────────┴────────┐
   │  规划 Planning│    │   记忆 Memory    │   │  工具 Tools      │
   └──────────────┘    └─────────────────┘   └─────────────────┘
```

### 3.1 规划能力（Planning）

- 把大目标拆成子任务、决定执行顺序；
- 通过**不同的提示词（prompt）**引导模型"按什么方式拆解任务"，比如后面要学的 **CoT（思维链，Chain-of-Thought）** 等提示词技巧；
- 课程原话：规划/拆解的能力源自大模型，是"核心大脑"给的。

### 3.2 记忆能力（Memory）

- **短期记忆**：如直接在对话框发给大模型的上下文；
- **长期记忆**：
  - 通过微调训练，把知识"压缩"进模型本身；或
  - **外挂知识库**（RAG 路线）——给模型外挂一个检索库，让它在回答时先查资料；
- 记忆的意义：执行完第一步要记得第二步，执行完分支任务要记得总目标——不能"捡了芝麻丢西瓜"。

### 3.3 工具使用能力（Tools）

- 拆解完任务后，需要用外部工具完成信息获取/计算，如**搜索工具、计算工具**；
- 把工具理解成传统应用里的 **API** 即可——应用里很多接口，各有各的作用，统称为工具；
- 有这三样东西，就能搭建出一个 Agent。

> **一句话记忆**：把 A 键（Agent）想象成你自己——你解决一个任务时的流程是什么样，Agent 大致也是这么干的。不要太被网上抽象概念吓到。

## 4. 多智能体协作：为什么要"多"而不是"一"

**单 Agent 的局限**（课程用"一个人干全栈项目"类比）：

- 老板把"项目架构设计 + 前后端 + 性能优化 + 测试 + 上线"全丢给一个人，还要当天上线——不现实；
- Agent 也一样：任务太杂、什么都会，但**每样都不精**；
- 已有研究发现：**让 Agent 专注在一个场景里，效率和准确性更高**。

**多智能体协作的做法**：让不同智能体各司其职（挂不同模型、用不同工具、访问不同知识库），在它们之间做交互协作；还可以根据硬件设备做资源的动态规划。

## 5. 三种常见协同范式

### 5.1 上下级协同（Supervisor / Sub-agent）

```text
用户需求
   │
   ▼
┌──────────────┐
│  中控/主智能体  │ ← 接收需求、拆解任务、分配
└──────────────┘
   │      │       │
   ▼      ▼       ▼
 子Agent 子Agent  子Agent   ← 行程规划 / 机酒预定 / 攻略定制……
   └──────┴───────┘
          │ 汇总结果
          ▼
       用户
```

- 特点：主智能体拆解后**下发给子智能体**，子智能体执行并返回，最后汇总；
- 典型例子：**飞猪**——主智能体把"行程规划、机酒预定、攻略定制"分别交给不同子智能体。

### 5.2 师生式协同（Teacher-Student）

- 一个"专家 Agent"负责整体策划与信息收集，把结果交给"学生 Agent"（或反过来两者讨论）；
- 更像**师生之间的讨论**，而非"严格执行"；
- 类比：你给大模型提需求 → 模型给一大堆 → 你说"太长了精简一点" → 模型再精简输出——这种多轮迭代就接近师生式协同。

> 与上下级协同的最大区别：上下级是"按我说的执行"；师生式是"来回讨论修正"。

### 5.3 竞争式协同（Competitive / Ensemble）

- 多个 Agent（方案 1、方案 2、方案 3……）各自独立产出结果；
- 最后比较哪个效果更好、择优输出——偏开放式讨论。

课程预告：整体协作方式还有很多种，后续会通过具体案例展开（下一课就是多 Agent 的客户数据分析实战）。

## 6. Agent 的应用形态

有了 Agent，市面上已经出现很多典型应用：

- **AI 智能客服**；
- **AI 数据分析师**；
- **AI 编程助手**：如 **Cursor**（课程提到）、CodeBuddy / Claude Code 等（字幕"克拉巴蒂"疑为同类工具，存疑未确认）；
